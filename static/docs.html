DocShield API v1Demo UI

All endpoints except /api/v1/health require the header X-API-Key.

MethodPathBodyReturns
GET/api/v1/health-Status, which integrations are enabled
POST/api/v1/documentsmultipart fileJob: threat scan + parsed document (type, fields, line items, entities, summary, validation)
GET/api/v1/documents-Recent jobs
GET/api/v1/documents/{id}-Stored job result
POST/api/v1/threats/filemultipart fileHashes, entropy, indicators, verdict, optional VirusTotal stats
POST/api/v1/threats/url{"url": "..."} or {"urls": [...]}Per-URL indicators and verdict
POST/api/v1/threats/text{"text": "..."}IOCs (IPs, URLs, domains, hashes, emails, CVEs), phishing signals, verdict

Example

curl -H "X-API-Key: demo-key-123" -F file=@samples/invoice_acme.pdf http://localhost:5003/api/v1/documents
curl -H "X-API-Key: demo-key-123" -H "Content-Type: application/json" \
     -d '{"url":"http://paypal.account-verify.top/login"}' http://localhost:5003/api/v1/threats/url

Verdicts: clean score < 30 · suspicious 30-69 · malicious ≥ 70. Indicator weights are combined with noisy-OR.
